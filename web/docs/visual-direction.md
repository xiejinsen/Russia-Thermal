# Web Visual Direction

status: CURRENT
selected_at: 2026-10-06
selected_prototype: /design-lab/intelligence/

## Current baseline

Keep the current light-blue Research Intelligence visual language as the working baseline.

Key characteristics:
- light blue / white research-tech palette;
- dark, readable body text;
- fixed left navigation on desktop;
- high information density without dark-dashboard aesthetics;
- readable table / matrix / status text;
- restrained heading scale;
- technical intelligence feel rather than marketing landing-page feel.

## What is frozen for now

Do not restart broad visual-style exploration unless a clear usability problem appears.

Preserve:
- left navigation model;
- light-blue technology visual language;
- compact but readable typography;
- table / matrix-friendly information density;
- clear China / Russia comparison color separation;
- restrained decoration.

## What remains flexible

Information architecture and section composition remain intentionally flexible.

Each module should be shaped around the question it answers. Do not force every section into the same card or grid pattern.

Required pyramid order:

1. Conclusion
2. So what / action implication
3. Why / theory basis
4. Evidence / drill-down
5. Boundary / next gate

A module may use:
- narrative summary;
- table;
- matrix;
- ranked list;
- comparison bands;
- decision log;
- evidence drawer;
- institution/person drill-down

depending on which form communicates the conclusion fastest.

## Production rule

The selected visual baseline is presentation-only.

Canonical research truth continues to come from GitHub objects:
SOURCE -> CLAIM -> ACTOR / CAPABILITY -> DIRECTION -> PRIORITY / DECISION -> SYNTHESIS.

The production Astro implementation should adopt this style only after the information hierarchy of the core modules is stable.
