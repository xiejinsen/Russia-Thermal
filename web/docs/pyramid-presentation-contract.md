# Pyramid Presentation Contract

status: CURRENT
scope: Figma, Canva, Astro, reports, leadership views

## 1. Principle

Every visible module must answer its management/technical question before presenting supporting detail.

Required order:

1. Conclusion
2. So what / action implication
3. Why / theory basis
4. Evidence
5. Boundary / next gate

A user should not need to infer the conclusion from evidence blocks.

## 2. Canonical ownership

- Global management conclusion -> SYNTHESIS
- Partner recommendation -> PRIORITY + linked DIRECTION
- Technical recommendation -> DIRECTION
- Demonstrated ability -> CAPABILITY
- Institution/person identity -> ACTOR
- Evidence proposition -> CLAIM
- Primary facts -> SOURCE
- State transition -> DECISION_EVENT

The presentation layer may shorten wording but must not invent or own strategy.

## 3. Module contract

Each major Figma/Astro module must declare:

- Question: what user question does this module answer?
- Conclusion: one sentence
- Implication: what the reader should do/remember
- Rationale: 2–4 concise supporting points
- Evidence entry: drill-down target(s)
- Boundary: what must not be inferred

If a module cannot satisfy this contract, it should not appear on a leadership page.

## 4. Progressive disclosure

Leadership layer:
- conclusion;
- implication;
- 2–3 reasons;
- one evidence affordance.

Technical layer:
- mechanism;
- comparator;
- capability;
- institutions / people;
- maturity / uncertainty;
- next gate.

Evidence layer:
- claims;
- sources;
- direct findings;
- boundary;
- provenance.

## 5. Figma responsibility

Figma owns:
- information hierarchy;
- visual hierarchy;
- component layout;
- typography;
- spacing;
- interaction intent;
- responsive behavior.

Figma does not own research truth.

## 6. Canva responsibility

Canva owns optional supporting media production:
- institution/person image treatment;
- diagrams/illustration assets;
- visual crops/backgrounds;
- report-ready graphics.

Canva assets require provenance and must not encode unsupported factual relationships.

## 7. GitHub/Astro responsibility

GitHub canonical objects own truth.
Astro maps normalized data into Figma-defined components.
No major page should contain hardcoded strategic conclusions that belong in canonical Synthesis/Direction/Priority objects.

## 8. Robustness target

A new monthly Source should normally require:
- no Figma change;
- no Canva change;
- no component change;
- no homepage copy change.

Only a semantic change to the management conclusion should alter the top-level narrative.
