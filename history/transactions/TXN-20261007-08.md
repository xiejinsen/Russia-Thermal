# TXN-20261007-08 — Research Coverage Dense Rows and Card Threshold

state: CLOSED
date: 2026-10-07
purpose: remove high-cardinality Capability card grids from Research Coverage and formalize a 15-item threshold for card-based collection layouts.

User-observed problem:
- Research Coverage still contained many Capability cards;
- support-only and comparator-only groups had grown beyond comfortable card-grid scanning;
- collection cardinality should automatically influence presentation choice.

Implemented:
- all four Research Coverage Capability disposition groups now use `DenseObjectRow`;
- one semantic row per Capability;
- consistent row treatment across Direction-linked / Support-only / Comparator-only / Background-killed groups;
- compact single-line sticky Explorer filter added for:
  - Country;
  - Disposition;
  - Direction;
  - full-text capability / actor / people / scope search;
- rows retain:
  - Capability statement / ID / disposition;
  - owner / key people;
  - strategic use;
  - transfer boundary;
  - maturity / evidence / target fit;
  - technical scope;
  - Direction status;
  - Claims / Evidence / Direction actions.

Low-cardinality elements intentionally remain card-like:
- 3 reading-path cards;
- 8 explicit Claim-role cards.
These remain below the new threshold and serve distinct orientation / interpretation purposes.

Design rule:
- 1–15 visible peer items: card layout is allowed when context benefits;
- >15 visible peer items: card grid must not be the primary collection pattern;
- when peer groups share one object class and any major peer group exceeds 15, prefer one consistent dense presentation across that object class.
