state: CLOSED
date: 2026-10-08

## Trigger

Before broadening research beyond the current phone-centric collaboration portfolio, review whether the existing web architecture can absorb:
- Russia-first institution capability mapping;
- publication and patent output timelines;
- collaboration history;
- international/influence signals;
- broader terminal/platform transfer;
- technical domains such as software thermal control and active/MEMS air cooling.

## Finding

The layered web architecture remains suitable, but the current normalized contracts and information architecture are optimized for Phase-1 Direction/Priority decisions.

Waiting until all Atlas data is populated would create an avoidable Level-2 shared-schema/UI migration.

## Preparation completed

- added `web/docs/capability-atlas-expansion-contract.md`;
- added a Russia-first Atlas journey to information architecture;
- reserved W8 Capability Atlas expansion in the web roadmap;
- defined additive future data contracts for collaboration, research-output snapshots and influence signals;
- explicitly prohibited stale aggregate counts on Actor;
- defined institution-lineage roll-up as an Atlas requirement;
- preserved current visible Phase-1 UI without empty placeholder modules.

## Important design decision

Existing P1/P2/P3, Direction, Russia-vs-China and Audit pages remain valid and are not repurposed as the Atlas.

The future Atlas is a separate view-model/presentation journey over the same canonical graph.

## Next dependency

Atlas implementation begins only after:
1. technical-domain vocabulary is frozen;
2. platform-transfer vocabulary is frozen;
3. collaboration relation ownership is decided;
4. research-output snapshot methodology is defined.

No research fact or Phase-1 strategic decision changed in this transaction.
