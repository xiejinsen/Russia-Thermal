# Collaboration Portfolio v0.1

Last reviewed: 2026-10-04

> **DRAFT SHELL — NOT A FINAL PARTNER RECOMMENDATION**

## Purpose

Convert technical hypotheses into a portfolio of partner-specific collaboration options.

The final report should not say only:
> "Lab X is strong."

It must say:
> "Lab X should contribute Y to PoC Z, because it owns capability A that complements our capability B and survives comparator C."

## Partner Card Template

### Partner / team

**Current verified people**
- PI
- key researchers
- current role
- contact
- last verified

**Distinctive capability**

What is actually hard to reproduce?

**Recent evidence**
2023–2026 primary papers, patents, projects, facilities.

**Reputation context**
University/lab/venue ranking metadata where useful.

**Why us / why now**

What can our side contribute that changes the value of the Russian capability?

**Background IP**

Known public patents / collaboration history / possible constraints.

**Proposed foreground IP**

Narrow joint control point.

**First 3–6 month package**
- data request
- sample/coupon
- model
- test
- review gate

**Success / kill gate**

**Readiness**
- technical discussion
- Stage-0 ready
- Stage-1 ready
- contract-ready
- not ready

## Final portfolio rule

The final report should recommend no more than:
- 1–2 primary collaboration targets;
- 1–2 reserve/watch targets.

A long partner list is not a strategy.
